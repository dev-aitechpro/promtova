## 1. Назначение

**Промтовая** — это локальное веб-приложение (SPA) класса «IDE для промпт-инжиниринга».
Это персональная база промптов для работы с LLM: хранение, организация по папкам/тегам,
переменные-шаблоны `{{var}}`, live-preview Markdown и быстрое копирование в буфер обмена.

Ключевые характеристики продукта:
- **Offline-first.** Все данные лежат в `localStorage` браузера, сервер не нужен.
- **Single-file distribution.** Через `vite-plugin-singlefile` сборка превращается в один
  самодостаточный `index.html` — его можно открыть как локальный файл без хостинга.
- **Локализация интерфейса:** русский язык (содержимое сид-промптов — на английском).

## 3. Архитектура

### 3.1 Layout
Трёхколоночный интерфейс (`App.tsx` → корневой `<div>`):
```
Sidebar (260px)  |  PromptList (340px)  |  Editor (flex-1)
   навигация            список промптов        редактор + preview
```
Поверх — модальные окна (`SettingsModal`, `ExportModal`, `FolderModal`, `ShortcutsModal`,
`ThemeEditorModal`) и стек тостов (`ToastStack`).

### 3.2 Состояние (3 Zustand-стора)
- **`usePromtovaStore`** — доменные данные и вся CRUD-логика: промпты, папки, теги, выбор,
  поиск, сортировка, переменные. Персистится (`name: 'promtova-state'`) с `partialize`
  (сохраняются `prompts`, `folders`, `selectedFolder`, `editorMode`, `sortBy`, `sidebarCollapsed`).
- **`useThemeStore`** — текущая тема + пользовательские темы. Персистится (`'promtova-theme'`).
- **`useUIStore`** — состояние модалок и тостов (не персистится).

Темы реализованы через CSS-переменные: `applyTheme()` проставляет `data-theme` и инлайн-переменные
на `:root`. В `index.css` заданы токены для `dark` и `light`; остальные пресеты
(`warm`, `ocean`, `mint`, `lavender`, `mono`) применяются программно из `presetThemes`.

### 3.3 Структура файлов
```
src/
  main.tsx                     — точка входа (StrictMode + createRoot)
  App.tsx                      — ВЕСЬ UI (~2080 строк, монолит)
  index.css                    — дизайн-токены, темы, анимации, стили md-рендера
  shared/types.ts              — Prompt, Folder, Tag, Theme, ExportData, EditorMode, SortKey
  store/usePromtovaStore.ts    — сторы данных/тем/UI + сид-данные (12 промптов, 4 папки)
  utils/cn.ts                  — clsx + twMerge
  utils/promtova.ts            — подстановка/извлечение переменных, Markdown→HTML,
                                 fuzzy-поиск, относит. время, счётчики, файлы
```

## 4. Модель данных (`shared/types.ts`)

- **Prompt**: `id, title, tags[], preview, path, content, vars{key:value}, starred, folder, createdAt, updatedAt, usageCount`.
- **Folder**: `name, parent, children[], icon?, color?, order`.
- **Tag**: производный тип (`id, name, count`) — пересчитывается из промптов (`recomputeTags`), не хранится отдельно.
- **Theme / CustomTheme**: набор CSS-переменных.
- **ExportData**: обёртка `.prmt` (version, exportedAt, prompts[]).

## 6. Анализ качества кода

### Сильные стороны ✅
- **Чистое разделение состояния** на 3 стора; `persist` корректно настроен через `partialize`.
- **Система тем** на CSS-переменных — гибкая, легко расширяется, нет «магии».
- **Single-file сборка** удобна для дистрибуции и офлайн-использования.
- **TypeScript strict** + `noUnusedLocals/Params` — высокая дисциплина типов.
- **UX-внимательность:** focus-rings, `aria-label` на иконках, empty-states, относительное время,
  анимации. Сид-данные (12 промптов) сразу демонстрируют возможности.

### Риски и недостатки ⚠️
1. **Монолитный `App.tsx` (~2080 строк).** Весь UI в одном файле — нарушение принципа
   единственной ответственности, сложно поддерживать, ревьюить и тестировать.
   → *Рекомендация:* вынести `Sidebar`, `PromptList`, `Editor`, модалки в `components/`;
   бизнес-логику — в `features/`.
2. **Нет тестов и линтера.** В `devDependencies` нет ESLint/Prettier/Vitest.
   → *Рекомендация:* добавить ESLint + Vitest, покрыть сторы юнит-тестами.
3. **Собственный Markdown-рендер через `dangerouslySetInnerHTML`.** `renderMarkdown` ограничен
   (нет вложенных списков, таблицы обрабатываются грубо) и потенциально уязвим при любом
   внешнем вводе (сейчас данные локальны — риск низкий).
   → *Рекомендация:* заменить на `react-markdown`/`marked` либо расширить и защитить санитайзером.
4. **Документация ≠ код по горячим клавишам.** В `ShortcutsModal` заявлены `⌘N` (создать) и `⌘F`
   (поиск), но обработчики в коде отсутствуют (реализованы только `⌘K`, `⌘S`, `⌘C`, `⌘⇧C`, `Esc`, `F2`).
   Также `⌘K` и `⌘F` помечены одинаково («Фокус на поиске»).
   → *Рекомендация:* либо привязать обработчики, либо убрать из списка.
5. **Потеря данных.** Всё в `localStorage` — очистка браузера удаляет базу. Авто-бэкапа нет.
   → *Рекомендация:* периодический авто-экспорт `.prmt` или импорт облака.
6. **`createTag` — no-op.** Теги только производные; метод оставлен «для совместимости API»,
   что вводит в заблуждение.
7. **UI тегов усечён.** `tags.slice(0, 12)` скрывает остальные теги из боковой панели.
8. **Хардкод метаданных.** «© Pavel K. / Neurocode», MIT — уточнить права и лицензию перед релизом.
9. **`partialize` не сохраняет `selectedPromptId`** → при перезагрузке выбор сбрасывается
   (компенсируется авто-выбором первого промпта — приемлемо).
10. **`node_modules` не установлен.** Перед запуском нужен `npm install`
    (спецификация зависимостей корректна: `lucide-react@^1.35.0` валиден).

## 8. Как запустить

```bash
npm install        # установить зависимости
npm run dev        # дев-сервер (Vite)
npm run build      # сборка в один index.html (vite-plugin-singlefile)
npm run preview    # предпросмотр сборки
```

После `npm run build` получается автономный `dist/index.html`, открываемый без сервера.
