## 1. Основная недоработка: UI автообновления не подключён (ТЗ v3 §3.4)

### 1.1 Проблема
`updater.cjs` шлёт события каналом `updater:event`, `preload` предоставляет `window.promtova.app.onUpdateEvent(cb)` и `installUpdate()`, но **в renderer нет ни одной подписки** — ни один компонент не вызывает `onUpdateEvent`. Пользователь не видит, что доступна новая версия, и не может перезапустить приложение для установки. Пункт ТЗ («Прогресс загрузки отображать в UI… уведомлением») **не выполнен**.

### 1.2 Задача
Реализовать лёгкий UI-слой обновлений, не засоряя персистентные сторы.

**Рекомендуемый подход — отдельный хуk + компонент уведомления:**
```
src/
  hooks/useAppUpdater.ts        // хук: подписывается на onUpdateEvent, хранит состояние обновления
  components/UpdateBanner.tsx   // баннер-уведомление (см. ниже)
```
- `useAppUpdater.ts`:
  - если `!window.promtova?.app` (веб/vitest) — возвращает `null`-состояние и не делает ничего.
  - поддерживает состояния: `idle | checking | available(version) | downloading(percent) | downloaded(version) | error(message)`.
  - на `update-downloaded` — показывает уведомление с **двумя кнопками**: «Перезапустить сейчас» (→ `installUpdate()`) и «Позже» (→ скрыть, не блокировать).
  - на `download-progress` — отображение процента (тонкий прогресс-бар).
  - на `error` — тихий лог + снятие баннера (не блокирует работу).
- `UpdateBanner.tsx` — компактный плавающий баннер (аналогично ToastStack по стилю, но с действиями), рендерится один раз в `App.tsx` (рядом с `<ToastStack />`).
- Не добавлять персистентного состояния — всё в `useState`/`useRef` хука (обновление — transient-событие, не переживает перезапуск).

### 1.3 Требования к UX
- Уведомление **не** перекрывает модалки и не мешает редактированию.
- Кнопка «Позже» скрывает баннер; при следующем успешном `update-downloaded` показать снова.
- При отсутствии сети/канала (`error`) — **никаких навязчивых сообщений**, только лог в консоль (сам `updater.cjs` уже отправляет `error`, в UI — игнор или краткий info-toast).

### 1.4 Приёмка UI обновлений
- В упакованном приложении при наличии новой версии на канале появляется баннер с версией; «Перезапустить сейчас» вызывает `quitAndInstall`.
- В веб-режиме (`vite dev` в браузере) и в vitest компонент рендерит `null`/ничего (без ошибок).
- Новые тесты: `useAppUpdater` — подписка, переходы состояний, отсутствие API в вебе. Без реального electron-updater (мок `window.promtova.app`).

## 2. Недоработка: иконка приложения (ТЗ v3 §7.1)

### 2.1 Проблема
При сборке: `default Electron icon is used (reason=application icon is not set)`. В `release\` установщик и `.exe` идут с дефолтной иконкой Electron.

### 2.2 Задача
- Создать `build/icon.ico` (многоразмерный 16/24/32/48/64/128/256) из существующего логотипа/бренда «Промтовая» (оранжевый акцент `#FF6B35`, форма — как favicon/лого, если есть; иначе простой аккуратный квадрат с символом).
- Если исходника лого нет — сгенерировать SVG → PNG → ICO (инструменты: `sharp`/`electron-icon-builder` в devDeps, либо внешний конвертер; результат зафиксировать в `build/icon.ico`).
- Подключить в конфиг electron-builder: добавить в `package.json` `build`:
  ```json
  "win": { "icon": "build/icon.ico", ... },
  "nsis": { "installerIcon": "build/icon.ico", "uninstallerIcon": "build/icon.ico", ... }
  ```
- Опционально: обновить значок окна (по умолчанию браузерный заголовок не показывает favicon) — в `index.html` манифест/иконку для веб, в Electron иконка берётся из `win.icon`.

### 2.3 Приёмка
- `npm run desktop:build` собирает установщик с **кастомной** иконкой (в логе нет `default Electron icon is used`).
- Иконка выглядит адекватно на 16px (ярлык) и на 256px (таскбар/обложка).

## 3. Сопроводительные правки

### 3.1 Пересборка графа знаний (AGENTS.md)
- Граф построен до Electron-слоя: `nativeStorage`/electron в графе отсутствуют, `graphify update` требуется.
- При пересборке исключить **ноду-мусор из git**: в графе присутствует `ccd1a0d Доработка по ТЗ v2: …` (`src=git`) — артефакт, попавший как «кодовая нода». Пересобрать с `--exclude "PROJECT_ANALYSIS.md"` и без захвата git-истории (или настроить exclude на git-ноды). После пересборки проверить `graphify query "nativeStorage"` → есть.
- Выполнять в конце сессии, после всех правок кода.

### 3.2 act() предупреждения в тестах (некритично)
- Vitest выводит `An update to XModal inside a test was not wrapped in act(...)`. Тесты не падают, но стоит почистить: обернуть переходы состояний в `act()`/`waitFor` (преимущественно в `App.test.tsx` и store-тестах).
- Цель: чистый вывод `npm test` без предупреждений.

### 3.3 Заглушки в publish-конфиге (только при публикации)
- `package.json` → `build.publish.owner/repo = "CHANGE_ME_OWNER"/"CHANGE_ME_REPO"` — реальный GitHub-аккаунт/репозиторий заполнить на этапе публикации релиза (не в коде). Оставить как есть для локальной сборки.
